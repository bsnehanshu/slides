Where Claude's compute comes from

What happens
  • Silicon: TSMC fabs, HBM from SK Hynix, Samsung and Micron, accelerators from Nvidia, Google and AWS
  • Training runs once per checkpoint and again for every model generation
  • Inference runs all the time and grows with usage
Why it matters

Training is a periodic cost. Inference is the bill that grows with your usage.

Two Bedrock endpoints, same price

What happens
  • bedrock-runtime: the default. Cross-Region inference, Guardrails, prompt routing, structured outputs
  • bedrock-mantle: server-side tools, web search, async, Projects and Workspaces
  • Mantle's Messages API rejects structured outputs with a 400
Why it matters

Per-token price is the same on both. Choose on capability, and start on runtime.

Claude on Amazon Bedrock · 4 of 7

Pick the endpoint, then the profile

What happens
  • Need server-side tools, web search, async or Workspaces? Use mantle
  • Otherwise use runtime, then pick by residency: in-region, geo (apac. au. jp. …) or global.
  • Need both? Split the workload across the two endpoints
Why it matters

Enforce the profile with an IAM condition on bedrock:InferenceProfileArn, plus an SCP.

Cross-Region inference: what moves

What happens
  • The request enters and returns through the source region

  • CloudWatch, CloudTrail, invocation logs and the price stay with the source region

Residency is a profile choice you can enforce, not a code change.

Claude on Amazon Bedrock · 6 of 7

Quota is reserved before you're billed

What happens
  • Runtime reserves input + max_tokens when the request starts
  • Output tokens count 5× against TPM (Claude 3.7 and later)
  • The bill counts actual tokens: 1,100 billed, but 1,500 TPM used
Why it matters

An oversized max_tokens causes 429s. Set it close to the output you expect.

Claude on Amazon Bedrock · 7 of 7

Decode is limited by memory, not compute

What happens
  • Every token rereads the active weights and the KV cache from HBM
  • The cores spend most of their time waiting on memory
  • Longer context means a bigger KV cache and more bytes per token
Why it matters

Batching, prompt caching and shorter context cut both cost and latency.
